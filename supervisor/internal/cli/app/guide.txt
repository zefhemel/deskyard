deskyard guide: how to work on a Deskyard desktop

WHAT A DESKTOP IS
A desktop is a Debian Linux container with an XFCE desktop and one shared
Chromium. A human uses the same desktop from their browser and may be
watching, or using the mouse and keyboard, while you work.

- One Linux user, `user`, home /workspace. Commands run as user, in
  /workspace by default. There is no sudo and no apt-get install.
- Only /workspace persists. Everything else is reset when the image is
  updated, so install into /workspace:
    mise use -g node@22 go jq      runtimes and CLI tools
    npm i -g PKG                   npm CLIs (~/.npm-global)
    uv tool install PKG            Python CLIs; uv run / uv venv for projects
    flatpak install --user -y --noninteractive flathub APP_ID   desktop apps
  Node and Python come preinstalled.
- Leave the desktop's services alone (Caddy, Selkies, Chromium, D-Bus,
  supervisord): killing them cuts the human off.

WHERE YOU ARE
- Inside a desktop: every command acts on it directly. No setup.
- Anywhere else: talk to it through a remote. A token comes from the
  desktop's Agents tab; then:
    deskyard remote add alice https://host/alice --token dyt_...
    deskyard -d alice status
  The first remote is the default; -d NAME or DESKYARD_REMOTE picks
  another. DESKYARD_URL + DESKYARD_TOKEN work without saving anything.
  A token reaches one desktop's shell, files, browser and desktop, nothing
  else. A stopped desktop answers "alice is stopped"; you can't start it,
  ask the human.

THREE WAYS TO WORK

1. Shell: for files, code, builds, tests, anything scriptable. Fastest and
   most reliable; prefer it.
    deskyard exec -- ls -la                    run a command, exit code passes through
    deskyard exec -- bash -lc 'cd app && npm test'   pipes, &&, globs need bash -lc
    deskyard exec --json -- cat notes.txt      {"stdout","stderr","exit"} in one object
    deskyard exec --cwd /workspace/app -e CI=1 -- make
    echo data | deskyard exec -- tee /workspace/in.txt   stdin is streamed
    deskyard cp ./src alice:/workspace/src     upload (file or directory)
    deskyard cp alice:/workspace/out.csv .     download
    deskyard terminal                         shared shell; detach Ctrl-B D
    deskyard shell                             interactive terminal (for humans)

2. Browser: for websites, especially ones that need the human's logins.
   The desktop's Chromium is shared: it is on the desktop, the human can
   see it, and it is signed in to whatever the human signed in to.
   Inside the desktop CDP is at http://127.0.0.1:9221. From elsewhere:
    deskyard -d alice browser connect &        forwards http://127.0.0.1:9222
   then attach (never launch your own browser):
    browser = p.chromium.connect_over_cdp("http://127.0.0.1:9222")
    page = browser.contexts[0].new_page()      your own tab, in the shared profile
   Open your own tab rather than taking over the human's; close it when
   done. browser.close() only disconnects. If a site needs a login, 2FA or
   a CAPTCHA, bring the tab to the front, tell the human exactly what is
   needed, and wait (poll the page) until they've done it.

3. Desktop: for anything without an API: desktop apps, browser UI outside
   the page (permission prompts, file pickers), or checking what the human
   sees. Slowest; use it when the other two can't.
    deskyard screenshot shot.png      look first (PNG; - or nothing = stdout)
    deskyard zoom 0 0 400 300 z.png   read small text in a region
    deskyard click 640 400            act by screen coordinates (pixels)
    deskyard type 'hello'             type into the focused field
    deskyard key ctrl+l Return        keys, xdotool syntax
    deskyard scroll 640 400 down 5
    deskyard drag 100 100 300 300
    deskyard wait 1                   let things load
   The loop: screenshot, find the target's coordinates in the image, act,
   screenshot again to verify. Coordinates are screen pixels (see
   `deskyard size`). Screenshots wait DESKYARD_SETTLE seconds (0.3) first.
   The human may move the mouse too: re-check before acting if things moved.

WHICH ONE
- Files, code, installs, data: shell.
- A web page, logged in or not: browser (Playwright over CDP).
- A desktop app, a dialog CDP can't reach, or "what's on screen": desktop.
- Combine them: shell to install and run, browser to drive the page,
  a screenshot to check the result.

PORTS
  Map TCP ports between your machine and a desktop (from outside it):
    deskyard -d alice forward 3000 &       your 127.0.0.1:3000 is localhost:3000 in the desktop
    deskyard -d alice forward -R 5173 &    the desktop's localhost:5173 is your 127.0.0.1:5173
  Mix several in one command (-R goes before each reverse one). Port
  order: plain LOCAL:DESKTOP (forward 8080:3000: your 8080 is the desktop's
  3000); after -R it is DESKTOP:LOCAL (-R 80:8080: the desktop's 80 is your
  8080). Loopback only; the desktop won't listen below 1024, so plain
  "forward 80" fails but "-R 80:8080" works (it only dials). On a lost link
  it reconnects by itself: -R local ports stay bound meanwhile, plain
  mappings come back in the desktop once the link is back. It prints "in
  LOCAL DESKTOP" / "out DESKTOP 127.0.0.1:LOCAL" and "Linked to ..." when the
  link is accepted, a moment before the desktop side is known to run.
  Limits: 4 links per token, 64 plain and 256 mappings per command. The
  humans see which ports your token maps.

WORKING ALONGSIDE A HUMAN
- They see every window you open. Don't close their tabs or windows.
- When you need them (a login, a decision), say exactly what and wait.
- Keep long-running programs in the background (setsid -f CMD) so they
  outlive your command.

MORE
  deskyard --help                 all commands
  deskyard COMMAND --help         arguments, an example, what it prints
  deskyard describe --json        every command as a machine-readable schema
Exit codes: 0 ok, 1 error (the message says what to do next), 2 usage error;
exec, shell and screen actions pass through the command's own exit code.
