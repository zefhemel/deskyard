# Selkies Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace KasmVNC with Selkies as each desktop's screen, sound, mic and webcam. Our desktop bar drives it:
- Clipboard, Keys, Quality, Lock size;
- an Audio panel, with mic badges;
- upload by dropping files onto the screen;
- a Download button.

**Architecture:**
- **The image** runs Xvfb plus `selkies --mode websockets` on 127.0.0.1:6080, behind Caddy's token, and its image contract becomes `3`.
- **The supervisor** serves Selkies' web client extracted from the image, with our additions served alongside. It proxies only the stream WebSocket (plus uploads), and adds its own file-list and download endpoints and a mic-state endpoint.
- **The desktop page** gets a Selkies adapter (`selkies.ts`) in place of `kasm.ts`.

**Tech Stack:** Selkies 2.1.x (pinned, from PyPI, with pixelflux and pcmflux), Debian Xvfb, PipeWire (speaker only), Go supervisor, Preact + TypeScript strict, pytest + Playwright (Chromium, Firefox, WebKit).

**Spec:** `docs/superpowers/specs/2026-10-22-selkies-design.md`. The prototype is on branch `claude/selkies-spike-98a338` (its write-up: `docs/superpowers/spikes/2026-10-22-selkies.md`). The pieces to reuse are on `audio-and-ports` (`e3f3684` and earlier).

## Global Constraints

- **Contract.** The image contract label is `deskyard.contract=3`, and the supervisor accepts only `"3"`.
- **What the supervisor proxies:**
  - `/<name>/screen/api/websockets`, the stream, which counts as viewing;
  - Selkies' upload endpoint, if uploads use HTTP.

  It serves no other desktop HTTP content; Selkies' client files come from the image, extracted per image ID. Session, access and same-origin checks apply as for today's `websockify`.
- **Nothing new as root** in desktops, and no new ports.
- **Selkies settings:**
  - WebSocket mode, no basic auth;
  - allowed origins = the supervisor's origins;
  - audio from `deskyard-speaker.monitor`;
  - CSS scaling on, browser cursors off;
  - `SELKIES_VIDEO_STREAMING_MODE=false`;
  - keyboard shortcuts off, sidebar hidden;
  - microphone on;
  - file transfers (uploads to `~/Desktop`) on, Selkies' own download off;
  - gamepads on;
  - webcam on only when a v4l2loopback device exists;
  - printing, screenshots and sharing off.
- **Upload:** at most 2 GB per file.
- **Download:** limited to `/workspace`, read as `user` through exec, a folder as a zip.
- **Mic and webcam** are always off on load or reconnect. Mic badges are per tab: `?tab=<random>` goes on the stream URL and `POST /api/desktops/{name}/mic {"on","tab"}`.
- **Desktop JSON and `viewers` events** become `{name, viewers, mics, forwards}`.
- **Browsers:** Chromium, Firefox and WebKit all show the picture, play sound and take input, clipboard, upload and download. Without WebCodecs the page shows "This browser can't show Deskyard desktops; use a current Chrome, Firefox or Safari".
- **Sync targets:** sound −45 to +125 ms from the picture, measured in Chromium, clean and at 60 ± 20 ms.
- **Browser storage keys** (`localStorage`, wrapped in try/catch): `deskyard.sound` (`{on, volume, output}`), `deskyard.mic.input`, `deskyard.cam.input`, `deskyard.lockSize`, `deskyard.quality`.

## Review Focus

- **A background tab that is the only viewer:** a second viewer who joins sees the picture within 5 s. Test: Task 6.
- **Dragging a window inside our frame** lands where the pointer is, not offset by the bar's 46 px. Test: Task 3.
- **Two viewers with their mics on at once:** the badges are right, and one turning off doesn't cut the other. Test: Task 4.
- **An upload over 2 GB** is refused with a clear message, and an interrupted upload leaves no partial file named as the original. Test: Task 5.
- **A path outside `/workspace` in Download** (`..`, absolute paths, symlinks out) is refused. Test: Track B.

## Parallel tracks

- **Track A (sequential, worktree `deskyard-selkies`):** Tasks 1 → 2 → 3 → 4 → 5 → 6 → 7.
- **Track B (independent, worktree `deskyard-download`, from `main`):** the Download endpoints and dialog. It merges into Track A before Task 7. Task 3 adds the bar button and calls the dialog through the interface below.

With STOP_VIDEO let through (a client without our additions), the joining viewer's picture came 2.5 s after joining.
