# Native terminal acceptance harness

Run against an isolated QA desktop and a named session. This harness sends shell commands and control bytes; never point it at a working personal session. The source is retained alongside evidence, outside the disposable SDD directory.

Generate the XCTest project with `xcodegen generate`, then run `xcodebuild test -project TerminalMobileQA.xcodeproj -scheme TerminalMobileQA -destination platform=iOS\ Simulator,id=DEVICE -derivedDataPath /tmp/terminal-mobile-build -collect-test-diagnostics never`. Select a single test with `-only-testing:TerminalMobileQA/TerminalMobileQA/testNativeAcceptance`.

Before running, authenticate a new Safari QA tab using the ordinary regular account, navigate to the preview terminal with `?session=ios-qa`, and enable the software keyboard. Record and restore the simulator's original hardware-keyboard preference. Existing device contents and unrelated tabs must be preserved. XCTest teardown may background Safari; reopen the owned URL before the next test. Uninstall only this QA test runner between builds if XCTest reuses stale installed tests.

Start `python3 proof_server.py --workspace HOST_WORKSPACE --container QA_CONTAINER --session ios-qa --output /tmp/terminal-proof.json`. Each launch creates a fresh nonce directory. Pass the generated proof_url and proof_path as `TEST_RUNNER_QA_PROOF_URL` and `TEST_RUNNER_QA_PROOF_PATH` environment variables to xcodebuild. The reader restores termios in finally and has a 45-second timeout. Verify bash before typing further commands after a failed test. The local HTTP server exposes only fresh proof files and the pane foreground process; terminate it after acceptance.

Commands and ordinary ASCII sequences use XCTest typeText. Native keyboard q and terminal helpers use native screen taps; backend files verify actual bytes and shell effects. Geometry assertions alone do not establish visual correctness: inspect screenshot attachments against Safari chrome and input accessory overlays. Extract attachments with `xcrun xcresulttool export attachments --path RESULT.xcresult --output-path OUTPUT`.

Final evidence: real iPhone picker create/join, keyboard input and dismiss/reopen passed on the refreshed production preview. At a real 36px landscape viewport the final UI displays the rotate-or-dismiss fallback while preserving the keyboard; returning to portrait recovers controls. Earlier overflowing landscape behavior is superseded. No native Unicode paste claim is made. Failed paste and login setup experiments are intentionally omitted from this reusable harness.

Final production flow: select `FinalTerminalQA/testFinalNative`, pass `TEST_RUNNER_QA_NEW_SESSION` with a fresh session name, and point the proof server at session `ios-qa`. Start the browser in that session. The test compares independently written shell PIDs across create/join, checks native Ctrl+C/Tab/q bytes, rotates while the keyboard stays open, and verifies dismiss/reopen. `testFinalPortraitVideo` emits QA_RECORD_START/STOP markers for external simctl recording. Portrait video evidence was transcoded to H264/yuv420p/faststart and fully decoded.

Landscape publication uses an actual native StaticText screenshot of the fallback to exclude unrelated browser tabs. Its full screen was inspected privately to verify the visible keyboard and text position; the element image alone is not keyboard evidence. The iPad full keyboard and Ctrl+C/Tab/q checks passed, with proof-only publication for the same tab-privacy reason. Native Unicode paste remains unverified.

Optional Android picker smoke: `python android_final_picker.py --state-dir PRIVATE_QA_STATE --cdp-url http://127.0.0.1:9227`, using Playwright and an already authenticated owned emulator Chrome tab. State contains private access.json (`url`, `name`) and a `data/NAME` directory bind-mounted as `/workspace`. It checks creation/rejoin via independent shell PIDs; this flow uses CDP, while earlier Android native keyboard proofs used adb taps. The status row is intentionally hidden at compact sizes, so readiness checks attached Connected text rather than visibility.
