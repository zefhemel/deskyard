A Deskyard terminal joins the same named Bash shell from a desktop browser, mobile browser, remote CLI, or native desktop launcher. Approved by the user on 23 October 2026, including on-screen keys and final native iOS simulator testing with the software keyboard open.

# Experience
The Terminal button appears beside Desktop. `/<name>/terminal/` opens the owned terminal page; `?session=NAME` and `deskyard terminal [session]` select a shell, default `main`. Session names match `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`. Connections detach independently. Shells and their jobs survive disconnection, but end when the container stops or restarts. Closing a shell shows an explicit reopen action rather than creating a replacement in a reconnect loop.

Use xterm.js bundled with the supervisor, and tmux installed in the common desktop image. No visible Zellij branding, patched vendor assets, separate terminal HTTP service, listener, or browser terminal credentials. The image-owned tmux configuration disables its status line, uses `window-size latest`, and leaves user configuration alone. A dedicated private runtime socket isolates Deskyard sessions from personal tmux servers. The most recently active client supplies the shared terminal dimensions; other clients keep a readable font and can scroll.

# Mobile
Use xterm's composition-aware input, with no synthetic password textarea or duplicate IME stream. Preserve native selection and paste; never autofocus after reconnect or a menu interaction. Size the terminal to the visual viewport above the software keyboard, including safe areas. At least 16px mobile input prevents Safari focus zoom. The key bar provides Ctrl-C, Ctrl-D, Ctrl-L, Esc, Tab, arrows, and one-shot Ctrl/Alt modifiers with accessible pressed state and 44px touch targets. Keys keep the software keyboard open and send terminal bytes through the same input path. Modifiers reset after use and disconnection. Test the bar in native iOS Safari with the software keyboard open, verify actual shell effects independently, and capture screenshots and short video.

# Transport and authorization
`GET /api/desktops/{name}/terminal?session=main` upgrades to a WebSocket after existing login, desktop View permission, running-state, and explicit same-origin checks. It executes owned `deskyard terminal-lease SESSION ATTACHMENT_ID` (non-TTY) and `deskyard terminal-attach ATTACHMENT_ID` (TTY) commands as user in `/workspace`, using a server-generated random attachment ID and never a browser-supplied command. The optional common image label `deskyard.terminal=tmux-v1` advertises this capability without changing contract 3. Older images show an actionable upgrade message before WebSocket upgrade rather than opening an unshared shell. Browser connections participate in viewer presence and therefore inhibit automatic idle memory reclamation.

Wire contract: first client text frame `{"cols":80,"rows":24}`; later client text frames `{"resize":[80,24]}` or `{"ack":N}`; client binary frames contain raw input bytes; server binary frames contain raw output bytes; server text frames contain `{"ready":true,"generation":"RUNTIME_GENERATION"}`, `{"exit":CODE}`, or `{"error":"MESSAGE"}`. Sizes must be 2–500 columns and 1–300 rows. Input frames are limited to 64 KiB; output uses 16 KiB chunks and at most 256 KiB unacknowledged per connection. The browser acknowledges only after xterm's write callback, and never queues or replays input while disconnected. Reconnection is bounded with backoff; authentication and protocol errors stop retrying. The generation includes container ID and runtime StartedAt, because Docker restart preserves container identity while ending shell jobs. Generation changes must explain that jobs ended. Backend writes and startup are bounded and canceled with the connection.

Logout closes that browser login's terminal connections; account deletion, access revocation, password/session epoch change, cookie expiry, desktop stop/delete/restart, and server shutdown close affected connections. Revalidate authorization after registration to close races. Terminal content and input must not enter logs or activity. Treat output as terminal data, disable automatic clipboard escape sequences, and avoid links with unsafe schemes.

# Attachment lifetime adjustment

Real Docker acceptance found that closing a TTY exec socket leaves its tmux client alive; the original single-helper transport was therefore superseded during implementation. Each remote attachment now has a non-TTY stdin lease owning a private `_deskyard_<ID>` grouped tmux session. It shares the persistent named base session’s windows and can be removed independently without killing shared panes or other clients. The lease watches EOF before creation, completes bounded creation before cleanup, and kills only its exact random group on EOF or cancellation. Docker forwards non-TTY EOF even after abrupt supervisor death. Attach-only execution cannot recreate a canceled group, and no extra listener/service is introduced.

Browser ready and remote CLI input forwarding wait for exact-client registration plus the first tmux terminal output, preserving that output for the renderer. The CLI still requests the exact owned `deskyard terminal-helper SESSION` through agent exec; the supervisor recognizes that TTY request and supplies the same two-process lifetime. Explicit stdin EOF detaches that client, while actual Ctrl-D bytes retain shell behavior. Local/native attachments continue to use direct tmux. The externally visible browser wire contract is unchanged.

# Browser implementation checkpoint
The owned browser page bundles stable xterm.js 6.0.0 and addon-fit 0.11.0 with full MIT notices. History enters tmux copy mode through its standard binding; PgUp/PgDn navigate and Esc returns. This is the supported history path because tmux uses the alternate screen and xterm 6.0.0 has an upstream touch-scroll regression. No vendor patch or claim that native touch scrolling is fixed is part of this implementation. The visual viewport below 300px uses one horizontally scrollable helper row; otherwise helpers use two rows. Native software-keyboard acceptance and the final root gate passed; the acceptance record below distinguishes native evidence, headless checks and unverified native Unicode paste.

# User amendment: native defaults and discovery

The user requested that all desktop terminal launchers open shared terminals and that the browser picker list all running terminals. A new ordinary native window/tab creates an independent shared session with a readable automatically allocated name (`terminal-1`, `terminal-2`, …), preserving its initial working directory. Explicit named CLI/browser joins retain their identities; public CLI without a name still joins `main`. Native default command preferences migrate at startup across XFCE, KDE and MATE, including existing workspaces. Explicit emulator commands and restoration commands preserve their argv and are intentional exceptions to default-shell creation. No personal tmux configuration is overwritten.

View-authorized `GET /api/desktops/{name}/terminal/sessions` returns `{"sessions":[{"name":"terminal-1"}]}` sorted by name, including detached-but-live shells and jobs, excluding private `_deskyard_` attachment groups. Empty is an empty array. Discovery uses a fixed owned helper with bounded runtime/output and exposes no content, input, command or environment. The picker refreshes on opening and during active use.

# Running-session picker and viewport amendment
The browser exposes running session names as explicit join actions with the active name marked, plus a separate validated new-name input and Create action. Names already listed cannot be created again through that form. Discovery refreshes on opening and every five seconds after the preceding request completes while the picker is visible; closing, hiding or changing desktop/session cancels its request and invalidates stale responses. Loading, empty, transient error and retry states retain the last successful names where useful. The response contains names only.

At short heights the picker’s existing-session list, refresh, close and create actions remain reachable in a horizontally scrollable 44px row within the visual viewport. Below the compact-layout budget (header50 + padded Reopen50 + helper44/top4/bottom inset of at least4 + terminal/padding28 + measured top inset), the page uses one 44px helper/navigation row without a separate header or vertical safe-bottom space. The minimum layout budget is 68px: one readable 24px terminal row plus 44px actions. Below 68px, a concise instruction asks the user to rotate to portrait or dismiss the keyboard; no smaller targets or Safari Hide Toolbar workaround is claimed. This instruction covers the clipped terminal without unmounting its transport/xterm instance or deliberately hiding/blurring its focused native textarea. Native iPhone acceptance proved that the keyboard remained open during the fallback and portrait restored usable input; the retained landscape image is a safe text-element crop, with the full keyboard frame verified separately.

### Native named-session joining (implemented finishing correction)

Within an existing native shared terminal, press **Ctrl-B then s** and choose the named session; this switches only that native client. The chooser shows public sessions, including browser-created shells, and the native title follows the selected name. Outside tmux, `deskyard terminal NAME` joins as before. Browser and remote CLI attachments keep their connection-owned groups: use browser **Sessions**, or detach and reconnect with `deskyard terminal NAME`, rather than the native chooser. The owned chooser filters private group rows and omits group metadata and initial previews. Advanced explicit tmux commands remain trusted-shell capabilities; this does not change lease ownership. Public base-session title options are applied on every ensure/join, including browser-created named sessions.
