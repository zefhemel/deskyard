Named shared Bash login shells run in the desktop's image-owned tmux server. `supervisor/internal/terminal` validates session names, produces the fixed helper argv, and creates or attaches exact session targets on `/run/workspace/deskyard-terminal/tmux.sock`; its enclosing directory is private (0700). Concurrent creation joins one shell, and canceling an attachment leaves the shell alive. Sessions end when the container stops.

`deskyard terminal [SESSION]` defaults to `main` and joins locally or through the existing remote interactive exec transport. The image-owned configuration at `/etc/deskyard/tmux.conf` disables the status line and uses `window-size latest`, without loading or overwriting personal tmux configuration. Shared shells default to `LANG=C.UTF-8`; user Bash login profiles may override it. Owned tmux clients explicitly enable UTF-8 even when their caller has no locale configured. `images/common/rootfs/usr/share/applications/deskyard-terminal.desktop` provides the native launcher across desktop images. The authenticated supervisor browser transport is implemented in `supervisor/internal/server/terminal.go`, `terminal_connections.go` and `terminal_flow.go`; the owned lazy browser page is implemented in `supervisor/web/src/terminal/terminal.tsx`, with key encoding, mobile controls and renderer-acknowledged transport in adjacent modules.

Desktop images advertise the optional `deskyard.terminal="tmux-v1"` capability alongside the unchanged `deskyard.contract="3"`. The supervisor uses this to provide an explicit upgrade requirement for older images without affecting their existing desktop workflows.

The browser endpoint executes only owned lease/attach argv and sends raw binary input/output, resize controls and renderer ACKs. Output credit is bounded at 256 KiB, chunks at 16 KiB and input messages at 64 KiB. Attachments count as viewers, inherit View authorization, and are canceled on logout, cookie expiry, epoch/access changes, lifecycle operations and shutdown. Container ID plus start time identifies the running lifetime, including same-container restarts. [[Architecture/Accounts]] owns signed login claims and [[Architecture/API]] exposes capability and transport contracts.

`supervisor/internal/terminal/lease.go` supplies each remote attachment with a non-TTY stdin lease owning a random private grouped tmux session, plus an attach-only TTY helper. EOF removes only that group and its client, preserving the named base session and shared panes even when the supervisor process dies. `supervisor/internal/server/terminal_process.go` shares this lifecycle between browser and the exact remote CLI helper request, waits for actual tmux output before input, and treats explicit CLI stdin EOF as detach. This supersedes the initial single-TTY-exec design, whose Docker socket closure left ghost clients. Native/local attachment remains direct tmux.

The browser keeps its native xterm textarea, accessible keyboard helpers and a visual-viewport layout above the software keyboard. History enters tmux copy mode with its standard prefix binding, PgUp/PgDn navigate and Esc returns; this provides explicit history access without relying on alternate-screen touch scrollback. [[Architecture/Web UI]] describes retry, reset, modifier and layout ownership. Pinned vendor licenses are bundled in `supervisor/web/public/assets/terminal-notices.txt`. Native iOS keyboard and final multi-client acceptance passed; [[Testing/Shared terminal 2026-10-23|Shared terminal testing — 23 October 2026]] records the evidence and remaining native paste, physical-device and amd64 runtime limits.

Native windows and tabs allocate independent readable names (`terminal-1`, `terminal-2`, …) through hidden `deskyard terminal-new`, using atomic tmux creation with collision retries and preserving the emulator’s cwd. The native window/tab title shows that same public session name through per-base tmux title options. Native tmux clients clear inherited tmux attachment markers to avoid treating a newly opened emulator as nested. Explicit `deskyard terminal [NAME]` retains exact-name joins and default `main`. The common `deskyard-terminal-configure` startup script migrates XFCE terminalrc/preferred-terminal settings, every saved MATE terminal profile as the desktop user. Explicit emulator command arguments still override the shared-shell default; user Bash/tmux configuration is untouched.

Authenticated View-scoped discovery at `GET /api/desktops/{name}/terminal/sessions` runs the fixed `deskyard terminal-list` helper, validates bounded output and returns sorted base-session names including detached shells. Private lease groups are filtered in both helper and supervisor parsing. `supervisor/internal/terminal/list.go` and `supervisor/internal/server/terminal_list.go` own this interface. No shell creation occurs while listing.

Within an existing native shared terminal, press **Ctrl-B then s** and choose the named session; this switches only that native client. The chooser shows public sessions, including browser-created shells, and the native title follows the selected name. Outside tmux, `deskyard terminal NAME` joins as before. Browser and remote CLI attachments keep their connection-owned groups: use browser **Sessions**, or detach and reconnect with `deskyard terminal NAME`, rather than the native chooser.
