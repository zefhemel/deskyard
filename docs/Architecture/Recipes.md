What a custom image is made from, and where it lives. A recipe has a name, a slug, a base (any catalog image, custom ones too), mise tools, Flatpak remotes and apps, and build commands. Recipes are kept in `.deskyard/recipes.json` (`internal/recipes/store.go`); the REST shape is in `supervisor/API.md`.

- **Tools.** One mise spec per line (`node@24`, `npm:@openai/codex`). They install system-wide into `/opt/mise`, and the build links their executables into the root-owned `/opt/deskyard/bin`, which is on `PATH` after the desktop's own mise shims. A desktop's own installs come first and override them.
- **Flatpak.** Apps come from Flathub by ID, from another remote (a `.flatpakrepo` URL, or a repository URL with a GPG key), or from a `.flatpakref` URL. They install system-wide in the image. Each extra remote's `.flatpakrepo` is saved under `/etc/deskyard/flatpak-remotes/`, and `workspace-init` adds it at user scope on every start, so a desktop can install and update from it.
- **Build commands.** One shell command per line, run as root after the tools and apps. They are saved in the image's `deskyard.recipe` label, so anyone who can inspect the image can read them.
- **From a desktop.** A recipe with `homeFrom: "image"` also carries a home template, `/opt/deskyard/home-template`. It is the chosen part of a desktop's home folder, and `workspace-init` copies it into a new, empty folder with `cp -an` as `user`, before the image's own skeleton. It never overwrites a file. Secrets are found by path and name (`internal/recipes/secrets.go`) and stay out unless ticked; any ticked secret marks the image `secrets`, shown as a lock badge, and the mark passes down to images built on it. Browser profiles are copied from an allow-list (`internal/recipes/browsers.go`): sign-in stores count as secrets.
- **Save as recipe.** Making an image from a desktop can also save a recipe on top of the result, to add tools later.
- **Base changes.** "Edit and rebuild" can pick another base; a base without the contract is refused. A custom image whose base has a newer image shows "Base updated".

The Dockerfile is generated by `internal/recipes/dockerfile.go`; the build itself is in [[Architecture/Image builder]].
