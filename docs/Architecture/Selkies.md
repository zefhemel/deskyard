Streams the desktop's screen, sound, mic, webcam and gamepads to browsers: Selkies 2.1.0 (in `/opt/selkies`, with a pinned pcmflux wheel and pixelflux 2.2.1 built from source) in WebSocket mode, as `user`, on `127.0.0.1:6080` behind [[Architecture/Caddy]], which passes only its stream (`/api/websockets`) and health probe through. The X server is Debian's Xvfb on display `:1` (a 3840x2160 framebuffer, modes added with `xrandr`); sound comes from the PipeWire speaker's monitor (`deskyard-speaker.monitor`), and Selkies' virtual mic is the default source. Pixelflux and pcmflux only run while someone is viewing. Settings: Turbo off, CSS scaling on, browser cursors, keyboard shortcuts, sidebar, printing, sharing and Selkies' own file transfers off (uploads and downloads are the supervisor's), mic and gamepads on (through Selkies' LD_PRELOAD joystick interposer in the session), and the webcam on only when the desktop has a virtual camera. The supervisor serves Selkies' web client from the desktop's image, not from the desktop (see [[Architecture/Desktop proxy]]). Files: `images/common/rootfs/usr/local/bin/start-xvfb`, `images/common/rootfs/usr/local/bin/start-selkies`, `images/common/rootfs/etc/supervisor/conf.d/workspace.conf`.

The image build applies `images/common/patches/client_hooks.py` to both executable copies of the exact Selkies 2.1.0 client. It checks their full SHA-256 before changing either and checks every replacement count, then advertises `deskyard-client-contract` version 1 in the page. A Selkies upgrade must review these call sites rather than accepting a fuzzy patch. The explicit boundary covers WebSocket URL/send/lifetime, input creation and gesture classification, cursor prediction, automatic focus, capture requests, playback context/output, playback worklet creation and capture errors. The supervisor's strictly typed adapter (`supervisor/web/src/selkies/`) implements those hooks; the client owns its private gesture state and browser calls. New images no longer require replacing browser prototypes, global constructors or private input methods.

The patched bundle installs native pass-through defaults from `images/common/patches/client_defaults.js` only when no supervisor adapter exists. This keeps the image’s direct Caddy client functional for rendering, viewport resize, input and media; the supervisor’s preloaded adapter takes precedence. Native defaults retain the original secure-context check, transport commands, capture/focus calls and touch-coordinate behavior, with local gesture overrides disabled. They do not change browser constructors or prototypes.

Over plain HTTP on a LAN address, the adapter permits Selkies' existing JPEG and WASM Opus fallbacks through its explicit preflight hook while retaining the browser's real insecure-context state. Playback worklet creation goes through a scoped ScriptProcessorNode fallback when AudioWorklet is unavailable; browser audio constructors and prototypes stay intact. The desktop page maps Quality presets to JPEG quality/frame rate, requests JPEG if needed, shows a "Not secure" note and disables mic/camera with "Needs https". Automatic clipboard still requires HTTPS; manual clipboard remains available. JPEG costs about six times H.264 bandwidth while the screen moves. Main-thread fallback audio can stutter under load.

Images built before the v1 marker continue using the original `screen_additions.js` compatibility bridge, including its version-specific interceptions. Upgrade the desktop image to enter the explicit-hook path. This bridge is retained for pre-contract Selkies 2.1.0 images until support is explicitly retired; unknown advertised contract versions show an actionable supervisor/image upgrade error.

Three Deskyard patches cut what an idle desktop costs (with one idle viewer, from about 7.5 % of a core to about 1.1 % with all three on; the audio gate is off as shipped, which adds back 0.6–1.4 %), applied at build time; the build fails if one doesn't apply exactly. pixelflux is built from source in its own Dockerfile stage (`pixelflux`) because one of them is Rust: the `2.2.1` source checked by SHA-256, its codec libraries (libvpx, SVT-AV1, dav1d, libde265, x264, x265) built by pixelflux's own wheel script and installed in `/opt/pixelflux/lib`, and Rust pinned in `RUST_VERSION`.

- **Key timers** (`selkies-key-timers.diff`): Selkies' key auto-repeat and stale-key loops sleep while no key is held, instead of running at 50 and 10 Hz from startup, viewer or not.
- **Idle grab** (`pixelflux-idle-grab.diff`): pixelflux skips copying and hashing the screen on a tick where X DAMAGE reported nothing and the encoder has settled, grabbing once a second as a keepalive; damage, a keyframe request or a new viewer wakes it at once. `PIXELFLUX_IDLE=0` turns it off; `PIXELFLUX_IDLE_AFTER_MS`, `PIXELFLUX_IDLE_KEEPALIVE_MS` and `PIXELFLUX_IDLE_QUIET_FRAMES` tune it.
- **Audio gate** (`selkies-audio-gate.diff`): stops recording the speaker after `DESKYARD_AUDIO_IDLE_S` seconds with no stream playing into it, and starts again when one does. **Off by default** (start-selkies sets `DESKYARD_AUDIO_IDLE_S=0`): it saves only 0.6–1.4 % of a core per watched desktop, and loses the first ~90 ms of every sound after silence, which swallows short sounds such as chat pings and the terminal bell without telling anyone. An image built on this one switches it on with `ENV DESKYARD_AUDIO_IDLE_S=3`.

Details and measurements: `images/common/patches/README.md`.

`images/common/patches/selkies-x-input-recovery.diff` makes the input event watcher retry a lost X connection every 500 ms, with at most one reconnect worker and the existing 20-second X reply/handshake timeout. The worker prepares the display, keyboard and mouse before publishing them together; failed initial connections also enter recovery. Lifecycle generations discard late results after disconnect or restart. A new connection resets cursor negotiation/cache and tracked pointer coordinates, and event-reader X errors enter the same recovery path. The installed-backend regression in `images/tests/native/selkies-input-recovery.py`, invoked by `images/tests/test_selkies.py`, uses a private Xvfb server and verifies real button/key delivery after a failed reconnect, initial-connection recovery and shutdown safety. It runs in each desktop variant's CI smoke selection. See [[Testing/MATE stream startup 2026-10-24|MATE stream startup investigation — 24 October 2026]] for the observed outage and scope of this fix.

The served client additions also recover a missing first picture after the mode handshake, primary pipeline reset or stream-resolution announcement: after 100 ms, they request a replacement keyframe if Selkies has not hidden its first-decoded-frame status marker, retrying at 250 ms intervals up to five requests. Recovery stops when a picture arrives or the transport changes/closes. This avoids waiting for the pinned client’s three-second startup watchdog when a join keyframe is lost. The serial background-viewer regression includes a deterministic case that withholds initial video until a replacement is requested.
