Preact + TypeScript (strict) + Tailwind, built with Vite and embedded in the binary: the desktops wall, a desktop's details page, images, accounts, login, and the desktop page at `/<name>/`: our own bar around [[Architecture/Selkies]]' client in an iframe (its sidebar hidden), driven through `web/src/desktop/selkies.ts`. The bar has who's viewing (with mic and camera badges), Audio (sound, volume, output, mic and webcam), Lock size, Clipboard, Keys, Quality and Download (a small file browser of `/workspace`); dropping files on the screen uploads them to `~/Desktop`. CLI clients’ on-screen actions are drawn over the picture. Updates live over server-sent events. The initial desktop list retries failed requests with exponential backoff from one second to thirty seconds, so a transient network failure does not leave the wall at “Loading…”. `web/src/live.tsx` owns the list and retry timer.

The Terminal shortcut moves into More below 640 CSS pixels so the mobile Apps, Audio, Clipboard and More controls remain reachable. The desktop toolbar uses its compact layout below 1024 CSS pixels: Lock size, resolution presets, Keys, Quality and Download move into More while Audio and Clipboard remain directly accessible. Shared menus scroll within the remaining visual viewport and recalculate their height on viewport changes (`web/src/components/menu.tsx`). Clipboard keeps drafts through unrelated window blurs and dismisses on a real interaction inside the screen frame (`web/src/desktop/clipboard.tsx`). See [[Testing/Mobile 2026-10-23|Mobile testing — 23 October 2026]] for the mobile checks and remaining device limitations.

The experimental Apps dialog (`web/src/desktop/applications.tsx`) uses the [[Architecture/Application bridge]] to list/launch applications and select existing windows. `window-viewport.tsx` crops/scales the full Selkies iframe, tracking known child dialogs with `window-view.ts`. A second bar offers Full desktop and Actual size/Fit window; phones have keyboard, touch/trackpad and common-key controls. Screen resolution is held during the crop, and focus/input remain shared. The full stream still reaches each viewer.

Full-desktop and focused-window touch controls (`web/src/desktop/touch-controls.tsx`) are shown by touch capability, including landscape/tablet widths. Tap and Trackpad are explicit choices, remembered per browser and reapplied on connection. Keyboard toggles the stream's input-assist focus through the adapter and follows actual focus changes. The desktop page follows `visualViewport` to remain above a software keyboard. `window-viewport.tsx` and `view-zoom.ts` apply anchored local pinch magnification from 1× to 4×, preserve the iframe's underlying dimensions while magnified, pan with two fingers at magnification, and expose Fit screen. The toolbar is outside the magnified picture; at fit, two-finger gestures still scroll the remote app. CLI action marks are hidden while locally magnified. These controls apply to existing Selkies images and are independent of the application helper.

The remote resolution dropdown beside Lock size offers 800×600, 1024×768, 1280×720, 1280×800, 1920×1080, 600×900 and 900×1200. Selecting a preset applies `lockSize`, saves the dimensions under the existing browser preference, and resets local magnification. Auto fit clears the preference and resumes following the viewport. Compact screens expose the same options in More. Only the display owner can change its shared resolution, and focused-window views require returning to Full desktop first. When unavailable, the compact menu keeps a disabled Resolution explanation visible instead of silently hiding the controls.

During an active single-finger Trackpad gesture, client pointer echoes (including pending relative motion) keep the cursor inside a 28-pixel viewport margin by scrolling the local view. This also works in Actual size window crops. The adapter compensates touch coordinates when parent scrolling moves the iframe, preventing stationary-finger feedback. Two-finger gestures, Tap mode and pointer movement from other viewers do not trigger following. No remote wheel events are generated.

The installable app shell uses `supervisor/web/index.html`, `public/manifest.webmanifest` and PNG icons derived from `assets/logo/app-icon.svg`. The manifest scopes standalone navigation to this supervisor and launches the desktop wall; the supervisor explicitly serves its manifest MIME type. There is no service worker or offline caching of authenticated pages, APIs or streams. Viewport-fit and safe-area CSS protect the status bar, home indicator, landscape notch and dialogs. iOS standalone mode reserves a 16-pixel solid edge below the top safe inset, keeping native top-edge blur off toolbar text. `desktop/viewport.ts` corrects the measured difference between `100lvh` and JavaScript layout height before applying the visual viewport during keyboard changes; ordinary browsers retain their existing geometry. Touch text fields use at least 16-pixel text to avoid iOS focus zoom. Native checks are recorded in [[Testing/PWA iOS 27|PWA testing — iOS 27]].

A running desktop's details page gives admins a **Reclaim memory** button (`web/src/components/reclaim-memory.tsx`). One click starts the request, disables the button while pending, and shows progress followed by measured resident bytes before/after or an error. The result explains that swapped pages may still use compressed RAM and identifies partial reclamation; shared toasts accommodate multiple lines within the phone viewport (`web/src/components/toast.tsx`). The button has no confirmation dialog; its tooltip notes that subsequent app interaction can be slower.

The button also depends on the host's cached boot-probe result from `GET /api/host`: it stays disabled while host capabilities load or if the startup probe failed. A failed probe shows its reason alongside the disabled button. The UI does not launch probes when opening a details page or polling host stats.

Desktop Settings has an **Automatically reclaim idle memory** checkbox (`supervisor/web/src/pages/details/settings-tab.tsx`), separate from settings that recreate the container. It saves immediately through `api.setMemoryPolicy`, survives reloads/upgrades and shows the host's capability failure reason when unavailable. It explains the 15-minute/no-viewers one-shot policy, busy skips and potential interaction delay; manual reclamation is independent of the opt-out.

The admin Settings tab has a Host folders editor (`supervisor/web/src/components/host-mounts.tsx`, `supervisor/web/src/pages/details/settings-tab.tsx`): up to 16 existing host source paths, non-overlapping desktop targets below `/mnt/` and read-only/read-write access. New rows default to read-only. Add/remove/edit and Undo participate in the existing settings Save job and container recreation warning. Host data is not deleted when a row is removed. The API client declares `HostMount` and `Settings.mounts` in `supervisor/web/src/api.ts`.


The owned terminal page at `/<name>/terminal/?session=main` lazy-loads bundled xterm.js 6.0.0 and addon-fit 0.11.0 through `web/src/terminal/terminal.tsx`; desktop tiles, details and the desktop bar link to it. `connection.ts` preflights the existing desktop API, then uses the current login cookie for the authenticated WebSocket. It discards disconnected input, sends binary input bytes and renderer-callback ACKs, retries consecutive transient failures with bounded jittered backoff, and stops on auth/protocol errors or shell exit. Online/pageshow can resume a pending retry. Each attachment queues a parser reset behind old renderer writes; socket ownership prevents stale callbacks acknowledging a new socket. Runtime generation is retained across lifecycle remounts to warn when shells/jobs ended.

`key-bar.tsx`, `keys.ts` and `terminal.css` provide accessible 44px keys, native composition/paste, one-shot modifiers, application-cursor-aware arrows and explicit keyboard focus. The visual viewport positions and sizes the page above the software keyboard; ResizeObserver fits it without shrinking its 16px font. Below 300px of visible height the two key rows become one horizontally scrollable row. `viewport.ts` derives a second tier below the occupied compact-layout budget (180px with zero safe insets, 196px with a 20px bottom inset; top insets add their measured height) that moves navigation/session access alongside the 44px helper row and removes redundant vertical insets/status space; one readable 24px terminal row and the helper row require 68px. Below that minimum, an explicit instruction asks the user to rotate to portrait or dismiss the keyboard. The terminal instance, transport and focused native textarea remain mounted under the clipped instruction so rotation does not deliberately blur input or disconnect the shell. Tmux History/PgUp/PgDn/Esc access works independently of xterm's alternate-screen scrollback; xterm 6.0.0's known touch-scrolling regression is not claimed fixed. Passive narrow clients may see tmux cropping until they interact under the latest-client size policy. Automatic OSC 52 clipboard commands are consumed; no unsafe link handler or terminal-controlled page title is installed. Full MIT notices ship at `/assets/terminal-notices.txt`.

`supervisor/tests/test_ui_terminal.py` checks real browser/tmux state, raw full-screen cursor mode, output flow, disconnect/reopen and emulated short viewports. Native software-keyboard acceptance remains the release gate in [[superpowers/plans/2026-10-23-shared-terminal|Shared terminal plan]].

`session-picker.tsx` lists running named shells through the View-authorized sessions API, distinguishes joining a listed shell from creating another name and marks the current session. `sessions.ts` owns single-flight requests with a six-second abort deadline, five-second refresh after completion, and cancellation/stale-response guards when the picker closes, the desktop/session changes or the document becomes hidden. Transient errors preserve the last list and expose retry; empty lists and loading are explicit. The panel bounds its list to the visual viewport; short layouts put session and create/close actions in a horizontally scrollable 44px row. Neither opening nor refreshing the picker focuses terminal input.

The details page’s Remote access tab creates and revokes access tokens for the CLI. The viewers popover labels tracked commands and screen actions as CLI activity, with terminal badges for clients and local programs. Existing `agents` tab IDs, JSON fields and internal component names remain compatible; the product wording does not change authorization or transport.

The administrator-only VPN connections page is `/_vpn` (`web/src/pages/vpn.tsx`), leaving the desktop name `vpn` available at `/vpn/`. It provides named NordVPN configurations, service-credential help, canonical country choices, disposable test/validation jobs and cancellation, reference-aware deletion and confirmed shared edits using the preview revision and stable desktop IDs. It shows each rollout result, including failures in a completed job, with links to retry the affected desktop. Secret inputs always start blank and omit blank edit values. Desktop creation and Settings use `web/src/components/vpn.tsx` for saved selections and port-specific local-network exceptions; `web/src/lib/vpn-form.ts` validates form payloads and distinguishes omitted settings from explicit No VPN. VPN health appears separately on desktop tiles, details and the desktop toolbar; regular accounts have read-only status. Current exit IP is shown only while connected, historical IP has its observation time, and idle status explains continued provider usage.

Candidate-test results remain associated with the last locally valid submitted form; a rejected retest cannot relabel an earlier success or exit IP. Desktop Settings compare canonical destination/transport/port policy and skip semantically empty PATCH requests, so accepted address or port normalization does not leave Save enabled or restart a desktop again. Explicit No VPN omits saved LAN rules and leaves hidden draft rows available until they are undone or edited. These form-lifecycle decisions are implemented and regression-tested in `web/src/lib/vpn-form.ts`.

Host-folder changes participate in the same canonical settings payload as VPN selection and LAN rules (`web/src/lib/vpn-form.ts`). A folder-only edit enables Save, combined edits use one job, and a completed save suppresses empty repeat submissions.
