Planned administrator-managed saved outbound VPN configurations, initially NordVPN service credentials and country selection. Reuse configuration across desktops while keeping each desktop's tunnel separate. Connection tests run in disposable runtimes; public API types omit secrets. Proposed implementation: `supervisor/internal/vpn/`, administrator routes in `supervisor/internal/server/` and settings in `supervisor/web/`. Configuration and credentials live under the supervisor's private `.deskyard/vpn/`, never in a desktop's workspace or image.

The storage foundation is implemented in `supervisor/internal/vpn/connections.go`: generated stable IDs, case-insensitive unique names, canonical NordVPN country choices, incrementing revisions and secret-free connection DTOs. The store takes the private `.deskyard` directory and writes metadata atomically in `vpn/connections.json`; read-only credential mounts use separate 0600 username/password files in 0700 version directories below `vpn/secrets/<connection-id>/`. Credential edits preserve existing mount files until the connection is deleted. Omitted credentials retain their saved values; write-only input rejects JSON serialization. Administrator routes, reference-aware deletion and the guided UI remain planned. Disposable candidate validation is implemented in `supervisor/internal/vpn/candidate.go`: `Test` validates a new candidate and `TestSaved` retains independently omitted credentials for an edit. Neither changes a live saved connection. Both use private temporary files and a disposable uniquely owned network/runtime, with a two-minute execution deadline and separate bounded cancellation cleanup. The runtime state, not raw provider logs, determines success; failures that cannot be classified honestly ask the administrator to check NordVPN service credentials (not the account login), country/server availability and host internet access. This does not claim that health alone identifies rejected credentials.

`supervisor/internal/vpn/policy.go` validates and canonicalizes private IPv4 destinations, TCP/UDP and explicit inclusive port ranges. It rejects public, link-local/metadata and IPv6 exceptions, merges equivalent rules and rejects all-port allowances, including effective port unions across nested destination prefixes. The managed runtime additionally validates overlapping control/other-desktop networks with `ValidateExceptionDestinations` and installs mandatory deny rules ahead of any exceptions. Its lifecycle caller must reserve the full configured desktop pool before recovery, including future allocations. No firewall is installed by the validation helpers themselves.
