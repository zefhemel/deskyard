Administrator-managed saved outbound VPN configurations, initially NordVPN service credentials and country selection. Reuse configuration across desktops while keeping each desktop's tunnel separate. Connection tests run in disposable runtimes; public API types omit secrets. Implementation: `supervisor/internal/vpn/`, administrator routes in `supervisor/internal/server/` and lifecycle settings in `supervisor/internal/desktops/`. The guided web UI remains pending. Configuration and credentials live under the supervisor's private `.deskyard/vpn/`, never in a desktop's workspace or image.

The storage foundation is implemented in `supervisor/internal/vpn/connections.go`: generated stable IDs, case-insensitive unique names, canonical NordVPN country choices, incrementing revisions and secret-free connection DTOs. The store takes the private `.deskyard` directory and writes metadata atomically in `vpn/connections.json`; read-only credential mounts use separate 0600 username/password files in 0700 version directories below `vpn/secrets/<connection-id>/`. Credential edits preserve existing mount files until the connection is deleted. Omitted credentials retain their saved values; write-only input rejects JSON serialization. Administrator routes and reference-aware deletion are implemented in `supervisor/internal/server/vpn.go` and `supervisor/internal/desktops/networking_connections.go`; the guided UI remains pending. Disposable candidate validation is implemented in `supervisor/internal/vpn/candidate.go`: `Test` validates a new candidate and `TestSaved` retains independently omitted credentials for an edit. Neither changes a live saved connection. Both use private temporary files and a disposable uniquely owned network/runtime, with a two-minute execution deadline and separate bounded cancellation cleanup. Network cleanup is armed before creation and uses its exact random attempt/name/ownership labels after an ambiguous engine response. Resource and private-file cleanup errors are sanitized and override a successful validation result. The runtime state, not raw provider logs, determines success; failures that cannot be classified honestly ask the administrator to check NordVPN service credentials (not the account login), country/server availability and host internet access. This does not claim that health alone identifies rejected credentials.

`supervisor/internal/vpn/policy.go` validates and canonicalizes private IPv4 destinations, TCP/UDP and explicit inclusive port ranges. It rejects public, link-local/metadata and IPv6 exceptions, merges equivalent rules and rejects all-port allowances, including effective port unions across nested destination prefixes. The managed runtime additionally validates overlapping control/other-desktop networks with `ValidateExceptionDestinations` and installs mandatory deny rules ahead of any exceptions. Its lifecycle caller must reserve the full configured desktop pool before recovery, including future allocations. No firewall is installed by the validation helpers themselves.

Shared edits use a disposable candidate test before saving, require the exact affected desktop IDs and expected revision, and report per-desktop rollout results through jobs. Revision commit atomically disables job cancellation; operation/reference waits remain cancellable and post-commit cancellation returns 409. Discovered selected consumers without a recovery record reject edits with a repair conflict before the revision changes. Assignment, reference deletion and revision commit share a coordination boundary; incomplete replacements remain discoverable from the private intent journal. Successful provider authentication and native Linux release verification remain outstanding.
