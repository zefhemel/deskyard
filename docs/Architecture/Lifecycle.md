The lifecycle of desktops as jobs: create (reusing a folder that is already there), start, stop, restart, remove, change settings and upgrade. Active desktop settings are discovered from container labels. Managed network selections additionally persist full private recovery snapshots and desired power in `.deskyard/vpn/desktops.json`; list/get includes interrupted transitions even when the container is absent.

`supervisor/internal/desktops/networking.go` defines the provider-neutral runtime boundary, `networking_store.go` owns atomic snapshots, `networking_lifecycle.go` orders pair transitions, `networking_reconcile.go` repairs and observes them, `networking_connections.go` coordinates saved revisions/references, `networking_lock.go` provides cancellable reference admission, and `networking_phases.go` defines safe recovery diagnostics. Production uses the real VPN manager. Networking is configured, including the entire reserved allocation pool, before startup reconciliation in `cmd/deskyard-supervisor/main.go`.

Every lifecycle mutation uses one per-desktop operation lock, independent of the existing server busy/job marker. Before replacing a namespace the old desktop loses independent restart, stops, and desired intent is committed. Consumer removal precedes runtime removal; firewall/control readiness precedes creation in the returned namespace. Failed enabled transitions never restore a direct-network container. Stable ID, Caddy token, creation time, image, limits, camera and workspace survive recovery; a vanished host camera is removed through the same safe transition.

Central bounded observations and owned engine events publish changed public snapshots without per-viewer probes. A tunnel reconnect changes health, not desktop power. Poll also restores the durable desired power after a consumer exit or failed stop without replacing a healthy unchanged gateway. Pending transitions and removals are recovered before filtering ordinary direct selections, so an interrupted explicit disable retains its direct intent and safe diagnostic until completion. Stopping keeps the gateway idle; removing tears down the owned pair and intent while retaining the reusable connection and respecting the workspace deletion choice. Shared revision edits validate first, confirm the revision/reference preview, then report each desktop result. Assignment and deletion use the same coordination boundary. Explicit disable preserves omitted LAN rules for reuse.

Shared edits keep the job context cancellable through operation/reference waits and recheck cancellation immediately before saving. The job mutex serializes accepted cancellation with revision commit; only committed application detaches cancellation, and later cancel requests return 409. Missing recovery records for discovered selected consumers reject the edit before commit. Recovery failures persist a fixed operation phase in the journal and cached reason and log that phase without raw causes or private identifiers; startup/poll/start retries retain selected policy, including an explicit No VPN selection. Journal snapshot and final-removal persistence failures return fixed public errors and leave the in-memory committed intent unchanged.

The opt-in full supervisor harness in `supervisor/internal/server/vpn_e2e_test.go` preserves distinct stable desktop IDs and WireGuard peer identities across new Manager/Service instances. It checks idle/start/application restart, stopped gateway egress blocking, persisted namespace replacement, retained workspace/token, same-image recreation and removal. This models supervisor replacement and dependency loss; it is not a reboot of the Docker daemon or physical host. Tests never run unscoped reconciliation against the shared development engine.

The central scheduler starts passes every five seconds and on owned events, with eight shared observation/repair slots. Saturated passes skip records, and repairs can occupy a slot for up to three minutes. There is no bounded fairness or fleet-wide five-second freshness guarantee; public cached connected/current-IP observations do not independently expire while skipped. The verified scope is two desktops. Separating/deduplicating repair work and providing fair observations or stale-status expiry is a deferred scalability follow-up.

Start/stop/restart and the manual and automatic memory-reclaim actions reserve the same desktop operation slot used by recreate/remove jobs, so they cannot overlap. Reclamation reserves the existing running state without stopping apps, closing viewers or creating a lifecycle job. `supervisor/internal/server/memory.go` enforces administrator access, checks the running state and calls the optional [[Architecture/Engine adapter]] capability. Startup missing-camera recovery retains its own reservation; power-request camera recovery reuses the request's reservation.

Memory-preserving suspend/resume is not implemented. The [[superpowers/spikes/2026-10-23-desktop-suspend|Desktop suspend checkpoint spike]] verified checkpoint/restore of a minimal container on OrbStack, but found runtime compatibility, Chromium nested PID namespace and desktop filesystem-watch blockers for a full desktop on the tested CRIU 4.1 stack.

Automatic reclamation (`supervisor/internal/server/memory_idle.go`) checks every 30 seconds, serially, after 15 minutes continuously without viewers. Viewer join generations catch even joins/leaves between checks. Container identity/start time, supervisor restart and policy re-enabling reset the timer; each actual attempt consumes the absence's allowance, including failures. Busy operations, tracked CLI work and missing/stale idle status skip without consuming it. After acquiring the operation slot, it rechecks desktop identity/running state, viewers, policy and CLI activity. A viewer returning during an in-flight request does not interrupt applications or prevent reconnection.

The default-on per-desktop preference lives in `memory-policy.json`, keyed by stable desktop ID (`supervisor/internal/server/memory_policy.go`), so changing it needs no container recreation and upgrades retain it. The [[Architecture/API]] and [[Architecture/Web UI]] expose the switch. Automatic reclamation uses the [[Architecture/CLI activity]] tracker and an explicit idle [[Architecture/Activity stream]] heartbeat; legacy/missing/stale streams fail closed. Work that bypasses Deskyard activity reporting remains outside this detection.

Per-desktop host-folder settings are validated and preflighted before the current container stops. Direct and VPN-managed create/recreate paths use one shared preflight container for all folders and the optional Docker socket, with separate directory/socket type checks, strict read-only binds and cancellation-independent cleanup. They are stored in the `deskyard.setting.mounts` label and carried through the existing image/limit/camera recreation paths. Applying a mount change recreates the container, restarting a running desktop and preserving stopped state. Invalid saved mount labels prevent recreation rather than silently dropping configuration. Failed direct-network replacement restores the old mounts and attempts to restart the restored container when the old desktop was running. VPN-managed transitions preflight host folders before stopping the current desktop, persist the folder settings in their networking snapshot, and retain the committed network selection on failure instead of rolling back to direct networking. Detachment never deletes source data; file deletion remains scoped to the desktop's private workspace. Implementation: `supervisor/internal/desktops/host_mounts.go`, `supervisor/internal/desktops/host_preflight.go` and `supervisor/internal/desktops/service.go`.


Direct-network replacement recovery is implemented in `supervisor/internal/desktops/recreate.go`; its public entry coordinates with managed networking before dispatching to either recovery path. Before stopping/removing the current container, the supervisor atomically writes and synchronizes a mode-0600 record in `<data>/.deskyard/recovery/<name>.json`, including previous immutable image ID, logical image reference, stable identity, proxy token, settings, creation time and running intent. File and directory entries are synchronized. New containers carry `deskyard.setting.image` so creating from a pinned image ID retains the logical reference used for update checks. Creation, startup, readiness and final-inspection failures share bounded rollback; a running restored desktop must become ready before its intent is removed. Failed rollback retains the record, and normal operation reservations refuse that name until recovery succeeds.

Startup reconnects the supervisor to managed desktop networks before replaying recovery records, then performs existing missing-camera reconciliation. Recovery refuses a container with another stable desktop identity and preserves stopped/running intent, workspace and mounts. It never deletes the workspace. A missing image, unavailable mount or failed readiness can still prevent restoration; the error is logged and the private record retained for the next startup retry. The durable record protects recovery intent; a supervisor crash cannot preserve application memory that container replacement already ended.

Production operation callers use `Service.Reserve`, which returns an idempotent release function, for lifecycle and memory-reclaim exclusion. `Begin`/`Done` remain the underlying compatibility primitives; repeated release of an old reservation cannot clear a newer operation. Recovery alone reserves a pending journal through the underlying primitives so it can repair the blocked desktop.

Docker daemon access is a separate administrator-controlled boolean (`dockerAccess`, persisted as a desktop setting label). It defaults off and follows the same recreation, networking snapshots and recovery paths as other settings. Enabling preflights the engine-host Unix socket before stopping the current desktop; disabling recreates without the socket. This is host administrator capability for every desktop user and program, not an isolated nested Docker service. Directory-only host-folder validation remains unchanged.
