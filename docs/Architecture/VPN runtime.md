Planned managed Gluetun container per VPN-enabled desktop. It owns the bridge endpoint, published desktop port, tunnel and firewall; the desktop shares only its network namespace and gets no additional network privileges. Blocks direct internet fallback and home-network access, with administrator-configured destination/port exceptions. Existing agent port forwarding remains unchanged and is outside this feature's bypass-prevention scope.

The managed runtime implementation now exists in `supervisor/internal/vpn/runtime.go`, `runtime_config.go`, `control.go`, `firewall.go`, `status.go` and `candidate.go`. `NewManager` takes the engine, saved-connection store and private state directory. Before recovery or `Ensure`, the lifecycle caller must configure `SetReservedNetworks` with the entire desktop subnet pool (including future allocations) and any additional supervisor/control prefixes. `Ensure` also discovers engine network subnets, validates exception overlap and produces a stable policy identity. Covered network allocations do not change an already enforced policy. Reusing a matching runtime verifies readiness; changed configuration or a stopped dependency requires coordinated lifecycle replacement, rather than silently removing a consumer's namespace. `Remove` deletes only the owning desktop's explicitly labelled gateway and private runtime files. Creation cleanup is armed before the engine mutation and reconciles an exact unique attempt label, stable name, role and desktop ID after an ambiguous cancellation/transport response; a colliding unrelated name is preserved. Cleanup uses an independent bounded context without recursively acquiring the same desktop lock, and sanitized cleanup failures require reconciliation. Lifecycle integration and proxy target resolution remain planned.

The runtime pins `qmcgaw/gluetun@sha256:c2ee4191762fca6b6a3c3359a731198a95d9c9af4db32d466e223bf3a84e779b` and pulls it automatically when absent, with bounded cancellation and sanitized errors. NordVPN uses OpenVPN UDP port 1194 with versioned read-only username/password mounts. Generated control authentication and policy files live under `.deskyard/vpn/runtimes/<desktop-id>/` with owner-only permissions. The API binds localhost, grants the secret-bearing observer only status/public-IP reads and denies unmatched routes by default; desktop applications sharing localhost cannot read settings or mutate tunnel/DNS state without authentication. Only the gateway receives NET_ADMIN and `/dev/net/tun`; this component does not change desktop privileges or agent forwarding.

An ordered managed OUTPUT chain allows stateful reply-direction traffic and loopback, denies mandatory reserved destinations before administrator exceptions, permits explicit destination/transport/port pairs directly, blocks private/link-local/metadata destinations, and permits public traffic through `tun0`. Provider bootstrap returns to Gluetun's endpoint firewall and is restricted to the trusted root OpenVPN process. Docker's embedded resolver address `127.0.0.11` is dropped in raw OUTPUT before Docker's DNS redirection. IPv6 INPUT/OUTPUT/FORWARD are blocked. LAN exception routes use a destination-only table 169 and a priority 100 lookup ahead of Gluetun's WireGuard policy table; this table has no default route. A typed resolver-policy input currently supports only public DNS through the tunnel (`1.1.1.1:53`); custom DNS remains a separate design.

`Ensure` applies an overall two-minute setup deadline before acquiring the operation lock, covering network/runtime discovery, image preparation, Create, Start and final Inspect even when its caller supplies no deadline. Readiness has a 30-second bound and checks the complete ordered firewall, exception routing and authenticated control response independently of tunnel health. Status observations use a shared five-second cache per desktop with a four-second observation bound, including cancellable exec streams/exit checks; slow operations on another desktop do not hold the shared map lock. Connected requires both health and a fresh HTTPS public-IP observation. Disconnection clears the current IP while preserving the last verified IP and observation time; previously connected tunnels become reconnecting. Missing runtime/policy/control failures become sanitized blocked observations. Desktop disabled/stopped/idle presentation and event publication belong to the pending lifecycle integration.

`fixture_engine_test.go` and `testdata/README.md` provide an opt-in controlled WireGuard test with ephemeral keys and unique-label cleanup. OrbStack checks passed for actual tunneled HTTPS and DNS, reordered-policy rejection, host HTTP through tunnel loss, loss/recovery, gateway stop, default-denied LAN, a limited port exception, Docker DNS denial, blocked IPv6, control read/mutation authentication and independent desktop namespaces. This does not verify NordVPN/OpenVPN authentication, full desktop/proxy behavior or native Linux deployment. The component remains planned in the diagrams until the feature's release criteria pass.
